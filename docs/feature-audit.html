DECK LAB / QUALITY ASSURANCE

Feature audit · version 6.1

October 3, 2026 · Apple silicon macOS · Native SwiftUI build 10

All 21 workspaces were exercised in an isolated QA app. Eight automated suites passed. Three defects were fixed and rechecked. Live TCGplayer refresh in the native app remains an unresolved exception.

Open issue: native live pricing

The QA app received “TCGplayer returned HTTP 403” when refreshing a known printing. The app preserved its cached quote, timestamp and owned quantities, and displayed the failure. Two command-line live runs succeeded, returning a verified NM low of $0.19 from Mystify Games. That does not establish reliable native-app access. Treat current live refresh as unverified/unreliable; the report does not mark every feature fully passed.

Version 6.2 follow-up: predictable pricing recovery

Added a shared serialized request queue, bounded retries for transient failures, Retry-After handling, five-minute cooldown after access denial, explicit stale-quote labels and suppression of stale/failed price alerts with failed refresh state retained across restarts. The identified native and command-line clients still receive HTTP 403. Live access remains unresolved; old command-line success is not evidence of supported app access.

Fixed and included in the rebuilt app

  1. Card-library inspector: the grid could collapse while the detail text lost its usable area. The grid now expands and the entire inspector scrolls, keeping text and require/exclude controls reachable.
  2. Genesys point search: point metadata previously loaded only after switching to Genesys. It now loads independently of the selected format. Verified point-filter results from TCG mode and added an integration regression.
  3. Missing card statistics: missing ATK/DEF could satisfy extreme numeric bounds because sentinel numbers represented missing data. Active bounds now require an actual stat. Regression tests cover negative minimum ATK and an extreme maximum DEF.

The test runner also now invokes the Master Duel live test. Its argument parser was corrected so --live is not treated as a fixture filename. Added all-format live coverage, fetch cancellation and a full model integration suite.

Safety and remaining test limits

  • Mutating UI tests used a separate bundle identifier and a separate local store under work/qa-data. Production ownership, builds and recovery files were not used for test mutations. Only card/provider caches were copied into the QA store.
  • The rebuilt production app was compiled and its signature verified. The equivalent corrected QA build was restarted and visually checked. The existing production app was left running; reopen it to load version 6.1.
  • Checked the main workspaces at normal and reduced window width, enlarged artwork, command palette, Escape and Command-1 navigation. Dark/light checks from the preceding GUI pass remain applicable; this audit focused on functional workflows.
  • Coverage is feature/workflow based, not every card, every printing or every possible input. The 15-minute wall-clock refresh timer, physical offline network disconnection and physical printing were not exercised. PNG was rendered and validated programmatically; HTML with real artwork was exported through the native dialog.
  • Live endpoints and prices may change. Native 403 responses were not bypassed. Source/API failures remain visible and cached data stays labeled.
